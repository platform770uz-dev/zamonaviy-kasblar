# CRM: вход через Telegram в одно нажатие

Подтверждённый админ нажимает «CRM» в личном чате с `@myflow97_bot`. Сайт открывается внутри Telegram, вход выполняется автоматически. Логин и пароль вводить не нужно. Рядом есть «Веб-версия» для ноутбука: в ней вход идёт по общему PIN-коду, сервер хранит его в секрете Supabase, а не в публичной странице. При обычном открытии сайта вне Telegram остаётся вход по email для существующих аккаунтов.

## Порядок включения

Рабочий проект CRM: `uzivivmrixstxjvzkksz` (`config.js`). Не применять эти изменения к школьному проекту.

1. Проверьте существующие CRM-таблицы, RLS-политики и функцию `crm_qongiroq_yoz` в рабочем проекте. Скрипт рассчитан на установленный `1924_savat.sql` и существующую таблицу `tg_chatlar` из `1924_tg_bot.sql`.
2. В SQL Editor выполните `1924_tg_crm_login.sql`. Скрипт добавляет привязку Telegram к Auth и отдельные права CRM. Данные не удаляются; повторный запуск допустим. Если позже повторно запускаете `1924_savat.sql`, повторите и `1924_tg_crm_login.sql`, чтобы восстановить проверку Telegram-доступа в функции записи звонка.
3. Разверните Edge Function `crm-telegram-login` из одноимённой папки. Она использует уже существующий секрет проекта `TELEGRAM_BOT_TOKEN`; токен не нужно копировать в код. `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` доступны серверной функции автоматически. Сохраняйте запрет публичной регистрации пользователей.
4. Для функции `crm-telegram-login` отключите проверку JWT шлюзом: запрос ещё не имеет сессии. Сама функция проверяет подпись Telegram, срок данных и подтверждение админа. Это задано в `supabase/config.toml`; `tg-bot` также сохраняет собственную проверку секрета webhook.
5. В SQL Editor выполните `1924_crm_web_pin.sql`. Скрипт добавит отдельную общую учётную запись CRM и ограничение неудачных попыток PIN. Обычные пользователи и HR-админка к ней не получают доступ.
6. В Edge Functions → Secrets задайте `CRM_WEB_PIN` значением PIN. Не добавляйте PIN в репозиторий, HTML или сообщения. Веб-вход ограничивает попытки по IP и блокирует доступ после пяти ошибок на 15 минут.
7. Разверните Edge Function `crm-web-login` из одноимённой папки. Для неё тоже отключите `Verify JWT with legacy secret`: PIN-функция проверяет секрет сама. Функция выдаёт одноразовый Supabase login hash; почта не отправляется.
8. Опубликуйте новую `crm.html` и убедитесь, что GitHub Pages закончил обновление. Проверьте Telegram-вход, веб-вход по PIN и прежний вход email/пароль.
9. Обновите Edge Function `tg-bot` из репозитория. В меню подтверждённых админов рядом с Telegram CRM появится «Веб-версия». Существующим админам достаточно отправить боту `/start` один раз, чтобы обновить кнопки. Повторное подтверждение не требуется. Старые сообщения с обычными ссылками не меняются.

Для CLI, из корня репозитория с настроенным доступом к нужному проекту:

```sh
supabase functions deploy crm-telegram-login --project-ref uzivivmrixstxjvzkksz
# Секрет CRM_WEB_PIN предварительно задаётся отдельно в Supabase.
supabase functions deploy crm-web-login --project-ref uzivivmrixstxjvzkksz
# После публикации crm.html:
supabase functions deploy tg-bot --project-ref uzivivmrixstxjvzkksz
```

Обновление `1924_tg_all_deals.sql` из этого PR включает уведомления и для сделок, созданных вручную или импортом. Это отдельное обновление триггера и не заменяет SQL для входа.

## Как проверять на рабочем проекте

- Подтверждённый админ: `/start` → новая «CRM» → сайт открылся без формы пароля; сделки и задачи доступны.
- «Веб-версия»: введённый PIN проверяется только серверной функцией; PIN и auth token не записываются в URL или логи. CRM-сессия браузера хранится в `sessionStorage` вкладки.
- Доступ общего веб-аккаунта можно немедленно отозвать: `update public.crm_web_login set enabled = false, updated_at = now() where id = 'shared';`. Запись RLS блокирует уже выданные сессии. Для повторного включения установите `enabled = true`.
- Общий PIN даёт полный доступ к сделкам CRM всем, кто его знает; доступ к HR и кандидатам остаётся закрыт. После пяти неверных вводов с одного IP вход блокируется на 15 минут.
- Человек без подтверждения не получает CRM-сессию. Копирование URL `crm.html?via=telegram` в браузер не даёт доступ.
- Владелец через `/adminlar` убирает доступ тестовому админу: новые запросы к базе блокируются сразу, открытая CRM показывает отказ при следующей проверке (до минуты). Повторное подтверждение возвращает вход.
- Прежний вход владельца по email и его доступ к кандидатам продолжают работать. Telegram-подтверждение предоставляет доступ только к CRM, не к HR-админке.

## Устройство и ограничения

Используются inline-кнопки `web_app` и кнопка меню чата: они передают подписанные `Telegram.WebApp.initData`. Сервер проверяет HMAC по токену бота и возраст данных (не более пяти минут). Кнопки обычной reply-клавиатуры `web_app` для такого входа не используются: они не передают нужные данные.

Сервер создаёт подтверждённому админу внутреннюю учётную запись с непредсказуемым служебным email и сохраняет её ID в `tg_chatlar.auth_user_id`. Затем выдаёт одноразовый хеш для Supabase `verifyOtp`. Письма не отправляются; хеш не добавляется в URL и не журналируется. Права определяются по `auth.uid()` и текущему подтверждению в базе, а не по данным, редактируемым пользователем. Блокировка действует и для уже выданной сессии.

Доступ к рабочему Supabase нужен для включения и проверки. Автотесты проверяют код и SQL на локальных фикстурах, но не подтверждают развёртывание или совместимость с неизвестными изменениями схемы рабочей базы.
